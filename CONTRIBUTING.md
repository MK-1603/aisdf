# Contributing

1. Open an issue describing the problem, affected domain and expected outcome.
2. Avoid duplicating existing guidance; update canonical files and link from indexes.
3. Cite authoritative sources for version-sensitive or normative claims.
4. Mark assumptions, unverified claims and limitations.
5. Do not add product adapters as VERIFIED without reproducible exact-version tests.
6. Do not add secrets, private project data or unlicensed third-party content.
7. Run `python tools/validate_repository.py` and include evidence in the pull request.
8. Explain compatibility, migration and security impact for schema/rule/workflow changes.
9. Obtain maintainer approval for governance, security, rule-precedence and license changes.
