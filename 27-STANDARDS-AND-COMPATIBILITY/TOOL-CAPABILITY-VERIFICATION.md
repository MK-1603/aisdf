# Tool Capability Verification

Verify exact product, version/build, plan/edition, environment, region if relevant, permissions and tested action. Record capability, prerequisites, limitations, reproducible steps, result, evidence, date, verifier and expiry/review date. Status is VERIFIED, PARTIAL, EXPERIMENTAL, NOT_VERIFIED or DEPRECATED. A product being listed in documentation or a marketplace is not proof that a user account can access it.

## Additional detail (carried from the starter seed)
Before relying on an AI assistant, design tool, coding IDE, Git provider, MCP connector, CI runner or deployment provider, verify the exact capabilities needed.

Record product, official source, tested version/plan, date, verification method, supported operations, file/terminal/browser/network/Git access, authentication model, data handling, limitations, permissions, evidence and support status.

Statuses: `VERIFIED`, `PARTIAL`, `EXPERIMENTAL`, `NOT_VERIFIED`, `DEPRECATED`.

A capability claim is specific to a product version, plan, configuration and environment. Recheck when the workflow depends on it. Do not infer that a tool can push, deploy or access private repositories from its marketing description.
