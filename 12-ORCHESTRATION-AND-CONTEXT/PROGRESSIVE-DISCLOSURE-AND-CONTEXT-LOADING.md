# Progressive Disclosure and Context Loading

Load context in this order: (1) project profile/state and mandatory rules; (2) current workflow and task contract; (3) directly relevant engine/domain docs; (4) linked decisions and evidence; (5) optional background references. Prefer canonical files and links over duplicated copied content. Record what was inspected and what remains unavailable. Context reduction must not remove constraints, permissions, acceptance criteria or unresolved risks.

## Additional detail (carried from the starter seed)
## Three levels
1. Essential: rules, steps, inputs, outputs, approvals and checks. Always load.
2. Practical: examples, implementation guidance, tradeoffs and common errors. Load when useful.
3. Advanced: internals, edge cases, scaling and specialist guidance. Load on request or risk/complexity trigger.

Never hide security boundaries, permissions, destructive-action warnings or mandatory verification in advanced material.

Load the minimum sufficient accurate context: core rules, project baseline, current task, relevant engine/workflow, current knowledge sources and required handoff. Do not omit critical context merely to reduce tokens.
