# AISDF Core Principles

1. **Evidence over claims:** distinguish observed facts, source-backed statements, assumptions and unknowns.
2. **Approval first:** consequential scope, architecture, cost, data, permission and release decisions require the designated approver.
3. **Least privilege:** tools and agents receive only the access needed for the assigned work.
4. **Change Only Law:** inspect the baseline; change only approved scope; preserve unrelated behavior; report every material change.
5. **No AI Slope:** no unnecessary features, abstractions, dependencies, architecture changes or token-heavy exploration.
6. **Traceability:** connect problem → requirement → design → task → change → test → evidence → release.
7. **Freshness and provenance:** version-sensitive claims need dated authoritative sources and review dates.
8. **Full completion:** do not mark done until required outputs, checks, evidence and state updates exist.
9. **Independent verification:** critical work should be checked by a separate reviewer or independent method when feasible.
10. **Right-sized engineering:** complexity must be justified by requirements, risk, scale or operational constraints.
11. **User-intent preservation:** do not silently reinterpret or replace approved product intent.
12. **Honest limitations:** report unverified capabilities, skipped checks, residual risks and blocked work.
