# File Naming Standards

**Status:** PROPOSED

- Canonical Markdown files MUST use uppercase words separated by hyphens, e.g. `KNOWLEDGE-FRESHNESS-POLICY.md`.
- Engine IDs and workflow IDs MUST remain stable; descriptive slugs MUST use lowercase kebab-case, e.g. `E-008-gap-conflict-ambiguity.md`.
- Avoid spaces, commas, parentheses, trailing periods and ambiguous abbreviations in canonical filenames.
- Use conventional extensions: `.md` docs, `.json` structured contracts/data, `.yaml`/`.yml` configuration, `.py` Python tools, `.sh` POSIX shell, `.ps1` PowerShell, `.toml` tool configuration, `.csv` tabular exports, `.svg`/`.png` visuals, `.pdf` distribution copies.
- File extensions MUST match actual content. Do not rename a file merely to make it appear to be another format.
- Use one canonical file per topic; alternate formats are generated outputs, not competing sources of truth.
