# Documentation Rules

- Use `.md` for human-readable canonical documentation; `.json` for machine-readable records/contracts; `.yaml` for human-edited configuration/templates; source-code formats only for executable tooling.
- Use `README.md` as the directory landing page. Do not create competing README variants in the same directory.
- Use uppercase, hyphen-separated names for canonical policy documents; engine files use `E-NNN-kebab-case.md`.
- Every document states purpose, status, owner/role, scope, inputs, outputs, related artifacts and review date where appropriate.
- Prefer one canonical source; link to it instead of copying policy text.
- Internal links must be relative and checked by validation.
- Mark examples as examples; never include real secrets or personal data.
