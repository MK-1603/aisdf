# End-to-End Lifecycle

1. **Intake:** classify the request and select Discover, Build or X-Ray & Improve.
2. **Analyze & validate:** normalize source material; identify facts, gaps, conflicts, risks and unknowns.
3. **Define:** establish stakeholders, requirements, scope, acceptance criteria and traceability.
4. **Design:** define UX/UI, technology, architecture, data/API and security decisions.
5. **Plan:** create milestones, dependency graph, work units, owners and approvals.
6. **Build:** implement bounded changes using authorized tools and controlled Git practices.
7. **Test & verify:** run applicable checks, independent review and acceptance verification.
8. **Deploy:** prepare environment and release only with authorization.
9. **Operate & maintain:** monitor, respond, update, deprecate and close out with evidence.

Every phase has entry conditions, outputs, exit criteria and handoff requirements. A blocked phase remains blocked; it is not silently bypassed.
